# Phase 2 Production Readiness — Deterministic AI Pathfinding

Phase 2 is production-ready only when every gate below is satisfied on the exact merge candidate and again on the merged `main` commit.

## Scope delivered

- Framework-independent `@snake/ai` package.
- Immutable AI observations derived from authoritative engine state.
- Deterministic orthogonal board graph with canonical neighbor ordering.
- BFS shortest-path search and reusable distance maps.
- Deterministic A* with Manhattan heuristic and stable tie-breaking.
- Food target planning across multiple targets.
- Current-tail route planning with explicit tail-cell traversal semantics.
- Deterministic candidate-move legality and **static-board** distance ranking.
- Search telemetry based on deterministic operation counts.
- Optional elapsed-time measurement only through an injected clock.
- Headless deterministic AI smoke runner.
- Open-board and dense-board 100×100 structural-bound tests.

## Hardened public contracts

### Search outcomes

BFS and A* share the same endpoint outcomes:

- `found`
- `unreachable`
- `invalid-start`
- `invalid-target`
- `blocked-target`

An out-of-board start is distinct from an out-of-board target. A target occupied by body, obstacle, or hazard is `blocked-target` unless that exact coordinate is supplied as `traversableTarget`. Valid traversable endpoints with no route are `unreachable`.

### Candidate telemetry

`CandidateMove.staticTargetDistance` is explicitly a shortest-path distance over the **current static blocked geometry**. It is not future-state simulation and must not be interpreted as a survivability guarantee. Multi-tick body prediction remains a Phase 3 concern.

### Isolation

Automated regressions prove that:

- observation creation deep-clones body, head, tail, food, obstacle, and hazard positions;
- mutating an observation cannot mutate source engine state;
- mutating the source after observation creation cannot mutate the observation;
- returned route coordinates do not alias caller start/target vectors;
- planner target coordinates are owned by planner results rather than observation objects.

## Determinism invariants

- Search must never call `Math.random()`, wall-clock APIs, browser APIs, timers, or storage APIs.
- Canonical neighbor order is `up`, `right`, `down`, `left`.
- Repeated identical observations and targets must return deep-equal search results.
- Search timing must not affect path selection or deterministic telemetry.
- Food ID ties use locale-independent code-unit ordering.
- Engine state must remain unmodified by observation creation or search.

## Correctness gates

The hardened merge candidate contains **62 passing tests across 18 test files**. Coverage includes:

- observation projection and deep reference isolation;
- body, obstacle, hazard, and board-edge blocking;
- explicit traversable target behavior;
- distinct invalid-start, invalid-target, blocked-target, and unreachable outcomes;
- BFS canonical shortest routes, detours, zero-length routes, and distance maps;
- A* shortest-path equivalence and deterministic tie handling;
- multiple-food selection with deterministic tie rules;
- current-tail planning;
- reversal, blocked-move, and vacating-tail candidate legality;
- explicit static-board candidate distance semantics;
- route and planner result ownership;
- injected timing;
- repeated search equality;
- open and dense 100×100 structural operation bounds.

## Performance invariants

For a 100×100 board, tests require search telemetry to remain structurally bounded by the 10,000-cell board size. The dense-board fixture additionally requires repeated results to be deep-equal and every returned route coordinate to remain in board bounds.

Wall-clock duration is intentionally not a correctness gate because hosted-runner timing is noisy; operation counts and board-size bounds are deterministic invariants.

## Build and dependency gates

The release candidate must pass:

```bash
pnpm install --frozen-lockfile
pnpm typecheck
pnpm test
pnpm build
pnpm check:forbidden
pnpm headless
pnpm headless:ai
```

`pnpm-lock.yaml` includes the `packages/ai` workspace importer and is generated by pnpm 10.15.0.

## CI gates

GitHub Actions verifies:

1. frozen dependency installation;
2. strict TypeScript typecheck across all workspaces;
3. all Phase 1 and Phase 2 tests;
4. production package builds;
5. forbidden nondeterministic/browser API scan across `shared`, `engine`, and `ai` sources;
6. two engine headless executions with byte-identical output;
7. two AI headless executions with byte-identical output.

## Architectural gates

- `@snake/engine` must not depend on `@snake/ai`.
- `@snake/ai` may consume engine types/read-only observations but must not own simulation state.
- Rendering, React, PixiJS, DOM, OBS, and UI types must not enter the AI package.
- Phase 2 is a static-board routing layer, not a future-state survival simulator.
- Phase 3 survival reasoning — flood fill, future-state simulation, trap scoring, food-safety rejection, risk scoring, Hamiltonian routing, and hybrid strategy switching — remains intentionally absent.

## Release procedure

1. Exact PR head passes the full frozen CI gate.
2. Final diff is reviewed for scope, deterministic behavior, mutation leaks, and performance regressions.
3. Branch is confirmed not behind `main`.
4. PR is squash-merged using an expected-head SHA guard.
5. The resulting `main` commit passes the same permanent CI workflow.

Only after step 5 may the hardened Phase 2 boundary be treated as production-ready and Phase 3 begin.
