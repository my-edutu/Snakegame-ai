## Hardened public contracts

### Search outcomes

BFS and A* share the same endpoint outcomes:

- `found`
- `unreachable`
- `invalid-start`
- `invalid-target`
- `blocked-target`

An out-of-board start is distinct from an out-of-board target. A target occupied by body, obstacle, or hazard is `blocked-target` unless that exact coordinate is supplied as `traversableTarget`. Valid traversable endpoints with no route are `unreachable`.

### Candidate telemetry

`CandidateMove.staticTargetDistance` is explicitly a shortest-path distance over the **current static blocked geometry**. It is not future-state simulation and must not be interpreted as a survivability guarantee. Multi-tick body prediction remains a Phase 3 concern.

### Isolation

Automated regressions prove that:

- observation creation deep-clones body, head, tail, food, obstacle, and hazard positions;
- mutating an observation cannot mutate source engine state;
- mutating the source after observation creation cannot mutate the observation;
- returned route coordinates do not alias caller start/target vectors;
- planner target coordinates are owned by planner results rather than observation objects.

## Determinism invariants

- Search must never call `Math.random()`, wall-clock APIs, browser APIs, timers, or storage APIs.
- Canonical neighbor order is `up`, `right`, `down`, `left`.
- Repeated identical observations and targets must return deep-equal search results.
- Search timing must not affect path selection or deterministic telemetry.
- Food ID ties use locale-independent code-unit ordering.
- Engine state must remain unmodified by observation creation or search.

## Performance invariants

For a 100×100 board, tests require search telemetry to remain structurally bounded by the 10,000-cell board size. The dense-board fixture additionally requires repeated results to be deep-equal and every returned route coordinate to remain in board bounds.

Wall-clock duration is intentionally not a correctness gate because hosted-runner timing is noisy; operation counts and board-size bounds are deterministic invariants.

## Architectural gates

- `@snake/engine` does not depend on `@snake/ai`.
- `@snake/ai` consumes engine state through detached observations but does not own simulation state.
- Rendering, React, PixiJS, DOM, OBS, and UI types do not enter the AI package.
- Phase 2 is a static-board routing layer, not a future-state survival simulator.
- Phase 3 survival reasoning — flood fill, future-state simulation, trap scoring, food-safety rejection, risk scoring, Hamiltonian routing, and hybrid strategy switching — remains intentionally absent.

## Superpowers hardening review

The review deliberately challenged endpoint semantics, deterministic ordering, mutation isolation, telemetry meaning, dense-board behavior, CI reproducibility, and phase-boundary discipline.

The review found and corrected production risks rather than merely confirming the existing implementation:

- separated invalid starts from invalid targets;
- distinguished blocked targets from valid-but-unreachable targets;
- centralized BFS/A* endpoint classification to prevent semantic drift;
- renamed candidate distance telemetry to prevent consumers from mistaking static routing for future survivability;
- expanded deep isolation and result-ownership regressions;
- expanded 100×100 testing to dense pathological geometry;
- preserved deterministic replay and byte-identical headless output.
